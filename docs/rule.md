# WeepCode 项目规则（rule.md）

> 本文件是所有开发者与 AI agent 必须遵守的项目规则。
> 与 `docs/codemap.md`（计划与硬门禁）、`docs/project.md`（架构）配套使用。
> 最后更新：2026-07-18

## 1. 命名规则（最高优先级）

**禁止任何意义不明的命名。** 名称必须让人不看实现就能知道用途。

### 1.1 禁止项

- 禁止无意义函数名：`handle_stuff`、`do_thing`、`process_data`、`helper`、`util_fn`、`foo`、`bar`、`tmp`、`test1`
- 禁止无意义文件名：`utils.rs`（大杂烩）、`misc.rs`、`common.rs`（无主题）、`new.rs`、`a.rs`、`mod2.rs`
- 禁止无意义变量名：`x`、`y`、`data`、`info`、`flag`（除非作用域 ≤3 行且语境自明）
- 禁止名不符实：名字说 A 实际做 B；函数名夸大或缩小其实际职责

### 1.2 必须项

- 函数名 = 动词 + 宾语，准确描述行为与返回值，如 `load_provider_profile`、`persist_model_override`
- 文件名 = 其内核心类型/职责的名词，如 `provider_setup_form.rs`、`anthropic_headers.rs`；一个文件一个主题
- 类型名 = 领域名词，如 `ProviderProfile`、`ApiBackend`
- 布尔量用 `is_/has_/should_` 前缀；异步任务带 `_task` 后缀； fallible 操作返回 `Result` 不裸 `unwrap`
- 命名语言：代码内一律英文（遵循 Rust 与项目惯例）；文档与注释可用中文
- 改名必须连带更新所有调用点与引用它的注释/文档，不留孤儿引用

### 1.3 评审口径

任何评审者（人或 agent）看到命名违规，必须当场指出并要求修正后才可合入。这是硬规则，没有"先合再改"。

## 2. 进度更新规则（强制）

**每完成一个可验证的工作单元，必须即时更新当天进度文件，不得攒批、不得事后补。**

- 路径：`docs/process/{YYYY-MM-DD}.md`（当天日期，如 `docs/process/2026-07-18.md`）
- 格式：按时间倒序追加条目，每条包含：
  - 时间、所属阶段（对应 codemap.md 的 Phase 编号）
  - 完成内容（具体到文件与行为）
  - 验证结果（实际跑过的命令与结论，如 `cargo check -p xxx` 通过）
  - 遇到的问题与下一步
- 当天文件不存在则新建，头部写日期与当日目标
- 跨天时，在新一天文件开头简述前一日遗留事项
- **门禁联动**：进度文件是硬门禁的验收依据之一。没有对应进度记录的工作视为未完成

## 3. 编码规则

- **最小改动**：只改实现目标所必需的代码；不顺手重构、不顺手格式化无关代码
- **遵循现有惯例**：新代码必须读起来像周边代码（注释密度、命名风格、模块组织），优先复用项目已有模式而非引入新风格
- **不假设依赖**：使用任何库/工具前确认 workspace 已依赖（查根 `Cargo.toml` 与邻近 crate 的 imports）；确需新增依赖要先说明理由
- **测试**：改动涉及的 crate 若有测试，必须通过；新增核心逻辑（如持久化、格式转换）要补单元测试
- **验证**：每个 Phase 收尾必须跑通 `docs/codemap.md` 规定的硬门禁命令，禁止"应该没问题"式收尾
- **文档同步**：改了架构、配置字段、命令、工作流，必须同 commit 更新 `docs/project.md` / `docs/codemap.md` / 相关用户文档；改了注释所描述的行为，必须同步改注释
- **完整性**：交付完整代码，禁止 `// ... 略` 式占位，禁止留待他人补全的半成品

## 4. Git 纪律

- 不主动执行 `git commit` / `git push` / `git rebase` 等变更操作，除非用户明确要求
- 不删除不认识的文件、分支、锁文件——先调查是否为他人在进行中的工作
- 破坏性操作（`rm -rf`、覆盖未提交改动）必须先获得用户确认

## 5. 文档结构约定

```
AGENTS.md            项目根，agent 入口规则（引用本文件）
docs/
  project.md         项目整体架构（审计结果，随架构变更同步）
  codemap.md         编码计划：阶段、checklist、硬门禁
  rule.md            本文件
  process/
    YYYY-MM-DD.md    每日进度（强制即时更新）
```
